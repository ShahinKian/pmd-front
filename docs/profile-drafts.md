# پیش‌نویس مرحله‌ای شناسنامه برنامه

در صفحهٔ صدور شناسنامه، «ذخیره مرحله» حتی اطلاعات ناقص را ذخیره می‌کند. «ذخیره و مرحله بعد» ابتدا اعتبارسنجی و سپس ذخیره می‌کند؛ در صورت خطای ذخیره به مرحله بعد نمی‌رود. پس از ورود مجدد، پیش‌نویس‌های همان حساب در بالای صفحه قابل ادامه‌اند. صدور نهایی همچنان از API فعلی انجام می‌شود.

## تنظیم سرور

پیش‌نویس‌ها روی دیسک سرور Next.js نگهداری می‌شوند، نه localStorage مرورگر و نه پایگاه داده PMD. برای محیط عملیاتی، مسیر ثابت خارج از پوشهٔ انتشار تعیین کنید و به حساب سرویس Node.js دسترسی خواندن/نوشتن بدهید. در `.env.production` مثلاً:

```dotenv
PROFILE_DRAFTS_DIR=C:/ProgramData/PMD/profile-drafts
```

این پوشه باید در پشتیبان‌گیری سرور قرار بگیرد و هنگام استقرار نسخه جدید حذف نشود. در چند نمونهٔ سرور، همه باید به یک فضای ذخیره‌سازی پایدار مشترک با پشتیبانی از قفل پوشه‌ای و تغییر نام اتمی متصل باشند. فضای موقت serverless مناسب نیست. بدون تنظیم متغیر، مسیر `.data/profile-drafts` نسبت به پوشه اجرای Node استفاده می‌شود.

هر حساب پوشهٔ جدا دارد؛ API هویت کاربر و دسترسی به پیش‌بینی را از PMD بررسی می‌کند. شماره نسخه از بازنویسی ناخواسته در دو تب جلوگیری می‌کند. فایل کامل با تغییر نام اتمی جایگزین می‌شود. قفل ذخیره پس از قطع ناگهانی فرایند، با مهلت ۱۰ ثانیه قابل بازیابی است. خطای دیسک به کاربر نمایش داده می‌شود و موفقیت ذخیره گزارش نمی‌شود.

## بازخوانی و اصلاح

- بازخوانی عوامل/آیتم‌ها درخواست تازه به سرویس اطلاعات پایه می‌فرستد و ردیف‌های حذف‌شده را بر اساس شناسهٔ منبع اضافه می‌کند؛ ردیف‌های ویرایش‌شده و دستی باقی می‌مانند.
- بازخوانی خودکار SWR دیگر فرم ویرایش‌شده را بازنویسی نمی‌کند.
- صدابردارها بر اساس نام سمت/فعالیت با یکسان‌سازی فاصله و نیم‌فاصله حذف می‌شوند.
- برای خطای پرسنل/سمت/فعالیت امکان تلاش مجدد وجود دارد. عنوان و مدت آیتم قابل اصلاح است؛ موضوع آیتم در پیش‌نویس حفظ می‌شود، اما قرارداد فعلی صدور PMD فیلد موضوع آیتم ندارد.
- اگر صدور موفق و ثبت کارشناسان ناموفق باشد، شناسه شناسنامه نگه داشته می‌شود تا تلاش مجدد همان شناسنامه را تکمیل کند.
